# ADR 0001: Migrazione a JDK 25 LTS

## Stato
**Approvata** (decisione di progetto, verifiche preliminari completate).

## Contesto
`groovy-math` utilizza il Foreign Function & Memory API (Panama FFM, `java.lang.foreign`) per collegare Groovy a librerie matematiche native ad alte prestazioni (LibTorch, ONNX Runtime, OpenCV, PETSc/TAO, OpenFOAM). In JDK 21 FFM era una funzionalità in anteprima che richiedeva il flag `--enable-preview` sia in compilazione sia a runtime. A partire da JDK 22 FFM è diventato standard definitivo (JEP 454), confermato ed ottimizzato nella release LTS JDK 25.

La migrazione a JDK 25 LTS consente di rimuovere `--enable-preview`, utilizzare le API finali FFM e garantire supporto a lungo termine.

## Verifiche preliminari (§A.0)
Prima dell'adozione del codice sono state verificate le seguenti condizioni di fattibilità:

1. **Gradle 9.6.1 Toolchain**: Supporta pienamente `JavaLanguageVersion.of(25)` secondo la matrice di compatibilità Gradle.
2. **Disponibilità JDK 25**: JDK 25 Temurin (`build 25.0.4.1+1-LTS`) è già presente nell'ambiente di sviluppo in `/home/igor/.gradle/jdks/eclipse_adoptium-25-amd64-linux.2`.
3. **JaCoCo 0.8.14**: Versione compatibile con bytecode class file major 69 (Java 25), verificata e disponibile nella cache locale.
4. **Security Manager e Sandbox AST**: In JDK 24+ il Security Manager è stato definitivamente disabilitato (`UnsupportedOperationException` su `System.setSecurityManager`). La sicurezza dell'esecuzione di script non fidati in `groovy-math` è garantita interamente a livello di compilazione Groovy tramite la sandbox AST (`MathDslSandboxCustomizer`), riscritta con un approccio ad allowlist rigorosa prima della generazione del bytecode.
5. **Compatibilità con Moqui Framework**: Il repository adiacente `moqui-framework` utilizza Apache Groovy 5.1.1 con target bytecode 21 (`sourceCompatibility = 21`). `groovy-math` adotta Apache Groovy 5.0.8 compilato con toolchain Java 25. Groovy 5.0.x/5.1.x garantisce piena interoperabilità binaria e sorgente a livello di libreria su JVM 25, consentendo l'integrazione di `groovy-math` come componente di runtime in `moqui-framework`.

## Decisioni tecniche
1. **Toolchain Gradle**: `java.toolchain.languageVersion = JavaLanguageVersion.of(25)`.
2. **Rimozione `--enable-preview`**: Eliminato completamente da `compileJava`, `compileGroovy`, `test`, ed `Exec` task.
3. **API FFM Standard**:
   - `MemorySegment.getUtf8String(offset)` sostituito con `MemorySegment.getString(offset)`.
   - `SegmentAllocator.allocateUtf8String(str)` / `Arena.allocateUtf8String(str)` sostituito con `allocateFrom(str)`.
   - Limitazione difensiva delle stringhe native a 4095 byte con terminatore NUL forzato sia in C++ che in Java.
4. **Manifest JAR**: Aggiunto l'attributo `Enable-Native-Access: ALL-UNNAMED` per la conformità a JEP 454.
5. **Rimozione JNI**: Rimozione completa di ogni rimasuglio JNI (`libtorch_jni.cpp`, `LibTorchBindings`, `LibTorchNative`).

## Conseguenze
- Build nativa e test eseguiti su JVM 25 senza flag di preview.
- Prestazioni FFM ottimali con Linker standard.
- La sandbox AST è l'unica linea di difesa per script non fidati.
